# ข้อความ Runtime Permission Dialog สำหรับ ChauatGo
## GPS และการแจ้งเตือนตามการใช้งานจริง

> **สถานะ:** ร่างข้อความ UI/UX สำหรับตรวจสอบและนำไปพัฒนา  
> **เวอร์ชัน:** 1.0  
> **วันที่:** 22 ตุลาคม 2569

หลักการของหน้าต่างชุดนี้คือ **ขออนุญาตเฉพาะเมื่อผู้ใช้เริ่มใช้ฟังก์ชันนั้นจริง** ไม่ขอ GPS การแจ้งเตือน กล้อง หรือรูปภาพตั้งแต่ First Launch และไม่รวมหลายวัตถุประสงค์ไว้ในปุ่มเดียว

ก่อนเปิด Native Permission ของระบบ เช่น `navigator.geolocation` หรือ `Notification.requestPermission()` ให้แสดงข้อความอธิบายของ ChauatGo ก่อนเสมอ จากนั้นจึงเปิดหน้าต่างสิทธิ์ของระบบ

---

## 1. กติกาการแสดง Dialog

1. แสดง Dialog หลังผู้ใช้กดปุ่มหรือเริ่มฟังก์ชันที่ต้องใช้สิทธิ์จริง เช่น `ใช้ตำแหน่งของฉัน`, `ปักหมุดจากตำแหน่งปัจจุบัน` หรือ `เปิดการแจ้งเตือน`
2. ระบุข้อมูลที่จะใช้ วัตถุประสงค์ ช่วงเวลาที่ใช้ และผู้ที่อาจเห็นข้อมูล
3. แยก GPS ลูกค้าออกจาก GPS ไรเดอร์ เพราะวัตถุประสงค์และความเสี่ยงต่างกัน
4. แยกการแจ้งเตือนสถานะงานออกจากการตลาด
5. มีปุ่มปฏิเสธหรือเลือกภายหลังที่เห็นชัด ไม่ใช้สีหรือการจัดวางเพื่อบังคับให้กดยอมรับ
6. หากปฏิเสธ ต้องมีทางเลือกทำงานด้วยการกรอกที่อยู่หรือเปิดสถานะเองเมื่อทำได้
7. ไม่เปิด Native Permission ซ้ำ ๆ หากผู้ใช้ปฏิเสธแล้ว ให้แสดงคำแนะนำไปที่การตั้งค่าระบบแทน
8. บันทึก Consent Event หรือ Permission Event แยกตาม `purposeCode`, เวอร์ชันข้อความ และผลลัพธ์
9. การกดอนุญาตใน Native Dialog ไม่ควรถือเป็น Consent สำหรับการตลาดหรือวัตถุประสงค์อื่น
10. ต้องรองรับการเปลี่ยนสิทธิ์ภายหลังจากการตั้งค่าเบราว์เซอร์หรืออุปกรณ์

# 2. GPS สำหรับลูกค้า

## 2.1 ใช้ตำแหน่งเพื่อค้นหาร้านใกล้ฉัน

**Trigger:** ผู้ใช้กด `ร้านใกล้ฉัน` หรือ `ใช้ตำแหน่งของฉัน`

**ไอคอน:** 📍

**หัวข้อ:**

> ใช้ตำแหน่งของคุณเพื่อค้นหาสถานที่ใกล้ฉัน

**ข้อความ:**

> ChauatGo จะใช้ตำแหน่งปัจจุบันของคุณเพื่อแสดงร้านค้าและสถานที่ใกล้เคียง รวมถึงช่วยจัดเรียงผลการค้นหาตามระยะทาง
>
> เราจะใช้ตำแหน่งเมื่อคุณเปิดฟังก์ชันนี้ และจะไม่ติดตามตำแหน่งเบื้องหลังเพื่อวัตถุประสงค์นี้ คุณสามารถป้อนตำแหน่งเองได้หากไม่ต้องการอนุญาต

**ปุ่ม:**

- ปุ่มหลัก: `อนุญาตให้ใช้ตำแหน่ง`
- ปุ่มรอง: `ป้อนตำแหน่งเอง`
- ลิงก์: `อ่านรายละเอียดการใช้ข้อมูลตำแหน่ง`

**Purpose Code:** `customer.location.nearby_search`

## 2.2 ใช้ตำแหน่งเพื่อคำนวณค่าส่งและจุดรับส่ง

**Trigger:** ผู้ใช้กด `คำนวณค่าส่ง`, `ใช้ตำแหน่งปัจจุบันเป็นจุดรับ` หรือ `ใช้ตำแหน่งฉันเป็นปลายทาง`

**หัวข้อ:**

> ใช้ตำแหน่งเพื่อคำนวณระยะทางและค่าจัดส่ง

**ข้อความ:**

> ChauatGo ต้องใช้ตำแหน่งของคุณเพื่อคำนวณระยะทาง ปักหมุดจุดรับหรือจุดส่ง และประเมินค่าบริการให้แม่นยำขึ้น
>
> ตำแหน่งจะถูกใช้กับคำสั่งหรือการจัดส่งที่คุณกำลังดำเนินการเท่านั้น และอาจถูกส่งต่อให้ร้านค้าหรือไรเดอร์ที่เกี่ยวข้องเฉพาะเท่าที่จำเป็นต่อการให้บริการ

**ปุ่ม:**

- ปุ่มหลัก: `อนุญาตและคำนวณระยะทาง`
- ปุ่มรอง: `เลือกจุดบนแผนที่เอง`
- ลิงก์: `ดู Privacy Notice`

**Purpose Code:** `customer.location.delivery_calculation`

## 2.3 ใช้ตำแหน่งเพื่อแชร์จุดหมายให้ไรเดอร์

**Trigger:** ผู้ใช้กดยืนยันคำสั่งส่งด่วนหรือเรียกไรเดอร์

**หัวข้อ:**

> ยืนยันตำแหน่งสำหรับการจัดส่ง

**ข้อความ:**

> เพื่อให้ไรเดอร์เดินทางไปยังจุดหมายที่ถูกต้อง ChauatGo จะใช้หมุดและที่อยู่ที่คุณเลือกในคำสั่งนี้ ไรเดอร์ที่รับงานอาจเห็นข้อมูลจุดรับ จุดส่ง และคำอธิบายที่จำเป็นต่อการจัดส่ง
>
> ตรวจสอบหมุดก่อนยืนยัน หากไม่ต้องการใช้ตำแหน่งปัจจุบัน คุณสามารถเลือกจุดบนแผนที่หรือกรอกที่อยู่เองได้

**ปุ่ม:**

- `ยืนยันตำแหน่งและเรียกงาน`
- `แก้ไขจุดหมาย`
- `ยกเลิก`

> หน้าจอนี้เป็นการยืนยันการเปิดเผยข้อมูลจุดจัดส่งตามคำสั่ง ไม่ควรใช้คำว่า “ยอมรับทั้งหมด”

**Purpose Code:** `customer.location.share_for_delivery`

# 3. GPS สำหรับไรเดอร์

## 3.1 ก่อนเริ่มรับงาน

**Trigger:** ไรเดอร์กด `เปิดรับงาน` หรือกด `รับงาน`

**หัวข้อ:**

> อนุญาตให้ใช้ตำแหน่งระหว่างรับงาน

**ข้อความ:**

> เมื่อคุณรับงาน ChauatGo จะใช้ตำแหน่ง GPS เพื่อคำนวณเส้นทาง อัปเดตสถานะงาน ช่วยให้ลูกค้าและร้านค้าที่เกี่ยวข้องเห็นความคืบหน้าที่จำเป็น และช่วยตรวจสอบความปลอดภัยของการจัดส่ง
>
> ระบบจะเริ่มใช้ตำแหน่งเมื่อคุณรับงาน และจะหยุดเมื่อส่งงานสำเร็จ ยกเลิกงาน หรือสิ้นสุดช่วงเวลาที่ระบุไว้ในนโยบายความเป็นส่วนตัว
>
> หากไม่อนุญาต คุณอาจไม่สามารถรับงานที่ต้องใช้การติดตามเส้นทางอัตโนมัติได้ แต่ยังสามารถติดต่อฝ่ายบริการเพื่อขอความช่วยเหลือได้

**ปุ่ม:**

- `อนุญาตขณะรับงาน`
- `ไว้ภายหลัง`
- `อ่าน Rider Privacy Notice`

**Purpose Code:** `rider.location.during_active_job`

## 3.2 เมื่อระบบต้องใช้ Background Location

หากระบบจำเป็นต้องใช้ตำแหน่งขณะหน้าจอแอปไม่ได้เปิดอยู่ ต้องแจ้งแยกอีกครั้ง ไม่ควรซ่อนอยู่ในข้อความขอสิทธิ์แบบทั่วไป

**หัวข้อ:**

> อนุญาตให้ติดตามเส้นทางขณะไม่ได้เปิดหน้าจอหรือไม่?

**ข้อความ:**

> เพื่ออัปเดตสถานะการเดินทางต่อเนื่อง ระบบอาจใช้ตำแหน่งขณะ ChauatGo อยู่เบื้องหลังในช่วงที่คุณกำลังปฏิบัติงานเท่านั้น
>
> การติดตามจะไม่ทำงานนอกช่วงรับงาน และคุณสามารถหยุดงานหรือเปลี่ยนสิทธิ์ได้จากการตั้งค่าอุปกรณ์

**ปุ่ม:**

- `อนุญาตเฉพาะระหว่างรับงาน`
- `ใช้เฉพาะเมื่อเปิดแอป`
- `ไม่อนุญาต`

> ต้องตรวจสอบข้อกำหนดของระบบปฏิบัติการและกฎหมายก่อนใช้ Background Location จริง เพราะมีความเสี่ยงสูงกว่าการใช้ตำแหน่งขณะเปิดแอป

# 4. การแจ้งเตือนสถานะงาน

## 4.1 ลูกค้า — แจ้งเตือนคำสั่งซื้อและไรเดอร์ใกล้ถึง

**Trigger:** ลูกค้ากด `ติดตามออเดอร์`, `เปิดการแจ้งเตือน` หรือหลังมีคำสั่งซื้อที่ต้องติดตาม

**หัวข้อ:**

> เปิดการแจ้งเตือนสถานะงานไหม?

**ข้อความ:**

> ChauatGo สามารถแจ้งเตือนเมื่อร้านรับออเดอร์ ไรเดอร์รับงาน ไรเดอร์ใกล้ถึง และงานเสร็จสิ้น เพื่อให้คุณเตรียมรับสินค้าได้ทันเวลา
>
> การแจ้งเตือนนี้ใช้สำหรับสถานะคำสั่งซื้อ ไม่ใช่การส่งโปรโมชั่น และคุณปิดได้จากการตั้งค่าอุปกรณ์หรือเมนูความเป็นส่วนตัว

**ปุ่ม:**

- `เปิดการแจ้งเตือนสถานะงาน`
- `ไว้ภายหลัง`
- `อ่านรายละเอียด`

**Purpose Code:** `customer.service_notifications`

## 4.2 ไรเดอร์ — แจ้งเตือนงานและความปลอดภัย

**หัวข้อ:**

> เปิดการแจ้งเตือนงานสำหรับไรเดอร์

**ข้อความ:**

> การแจ้งเตือนช่วยแจ้งงานใหม่ การเปลี่ยนแปลงคำสั่งซื้อ ข้อความจากลูกค้าหรือร้านค้า และเหตุการณ์สำคัญระหว่างจัดส่ง
>
> เราจะไม่ใช้สิทธิ์นี้เพื่อส่งโปรโมชั่น เว้นแต่คุณจะเลือกยินยอมการตลาดแยกต่างหาก

**ปุ่ม:**

- `เปิดการแจ้งเตือนงาน`
- `ไว้ภายหลัง`
- `ตั้งค่าภายหลัง`

**Purpose Code:** `rider.service_notifications`

## 4.3 ร้านค้า — แจ้งเตือนออเดอร์

**หัวข้อ:**

> เปิดการแจ้งเตือนออเดอร์ของร้านไหม?

**ข้อความ:**

> การแจ้งเตือนช่วยให้ร้านทราบเมื่อมีออเดอร์ใหม่ มีการเปลี่ยนแปลงรายการ หรือไรเดอร์กำลังเดินทางมารับสินค้า
>
> การแจ้งเตือนนี้เป็นส่วนของการจัดการออเดอร์ ไม่รวมข่าวสารการตลาด

**ปุ่ม:**

- `เปิดการแจ้งเตือนออเดอร์`
- `ไว้ภายหลัง`

**Purpose Code:** `merchant.order_notifications`

# 5. แยกการตลาดออกจากการแจ้งเตือนบริการ

ห้ามใช้ข้อความว่า `เปิดการแจ้งเตือนทั้งหมด` หากรวมการตลาดไว้ด้วย ควรใช้หน้าจอแยก:

**หัวข้อ:**

> รับข่าวสารและโปรโมชั่นหรือไม่?

**ข้อความ:**

> หากคุณเลือกยินยอม ChauatGo จะส่งโปรโมชั่น ส่วนลด และข่าวสารผ่าน [ช่องทางที่เลือก] คุณถอนความยินยอมได้ทุกเมื่อ และการไม่ยินยอมจะไม่กระทบต่อบริการสั่งซื้อหรือจัดส่ง

**ตัวเลือกที่ไม่เลือกไว้ล่วงหน้า:**

- `[ ]` รับผ่าน Push Notification
- `[ ]` รับผ่านอีเมล
- `[ ]` รับผ่าน SMS
- `[ ]` รับผ่านโทรศัพท์

**Purpose Code:** `customer.marketing` หรือ `rider.marketing` หรือ `merchant.marketing`

# 6. สถานะหลังผู้ใช้ตัดสินใจ

## อนุญาตสำเร็จ

> เปิดใช้งานแล้ว  
> คุณเปลี่ยนสิทธิ์ได้จากเมนู `บัญชีของฉัน > ความเป็นส่วนตัวและการอนุญาต`

## ปฏิเสธ

> ยังไม่ได้เปิดใช้สิทธิ์นี้  
> คุณยังใช้วิธีกรอกที่อยู่ เลือกจุดบนแผนที่ หรือดูสถานะในแอปได้ ฟังก์ชันบางอย่างที่ต้องใช้ข้อมูลนี้อาจไม่ทำงานครบถ้วน

## เคยปฏิเสธและต้องเปิดจากระบบ

> การอนุญาตถูกปิดไว้ในการตั้งค่าอุปกรณ์  
> หากต้องการใช้ฟังก์ชันนี้ ให้เปิดสิทธิ์ ChauatGo ใน `การตั้งค่าอุปกรณ์ > การอนุญาต` แล้วกลับมาอีกครั้ง

## เกิดข้อผิดพลาด

> ยังเปิดใช้สิทธิ์ไม่ได้  
> ลองใหม่อีกครั้ง หรือติดต่อฝ่ายบริการหากปัญหายังคงอยู่

ปุ่ม: `ลองอีกครั้ง` / `ใช้วิธีอื่น` / `ติดต่อฝ่ายบริการ`

# 7. การบันทึก Permission และ Consent Event

ทุกครั้งที่แสดง Dialog หรือได้รับผลลัพธ์ ควรบันทึก Event แยกกันใน Backend/Cloud Function ไม่ควรพึ่ง LocalStorage เป็นหลักฐานเดียว

ตัวอย่าง Field สำคัญ:

```json
{
  "subjectRef": "authUidOrPseudonymousId",
  "subjectType": "customer",
  "eventType": "consent_granted",
  "purposeCode": "customer.location.delivery_calculation",
  "policyId": "customer_location_policy",
  "policyVersion": "1.0",
  "noticeId": "general_privacy_notice",
  "noticeVersion": "1.0",
  "source": "web_app",
  "channel": "runtime_permission_dialog",
  "nativePermissionResult": "granted",
  "eventAt": "server_timestamp"
}
```

ผลลัพธ์ของ Native Permission ควรแยกจาก Consent ของธุรกิจ:

- `nativePermissionResult`: `granted`, `denied`, `prompt`, `restricted`
- `consentEvent`: `granted`, `rejected`, `withdrawn`

ตัวอย่างเช่น ผู้ใช้กด `อนุญาต` ใน ChauatGo แต่กดปฏิเสธใน Native Dialog ต้องบันทึกว่า Native Permission เป็น `denied` และห้ามถือว่า Consent สำเร็จ

- แจ้งเตือนสถานะงาน: `เปิด / ปิด`
- ข่าวสารและโปรโมชั่น: `ยินยอม / ไม่ยินยอม`
- รูปภาพและไฟล์: `ขอเมื่อใช้ฟังก์ชัน`
