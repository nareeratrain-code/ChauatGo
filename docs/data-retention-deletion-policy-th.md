## 1. หลักการสำคัญ

ChauatGo จะเก็บข้อมูลส่วนบุคคลเท่าที่จำเป็นต่อวัตถุประสงค์ที่แจ้งไว้ ต่อการปฏิบัติตามกฎหมาย ต่อการปฏิบัติตามสัญญา หรือต่อการก่อตั้ง ใช้ หรือยกขึ้นต่อสู้สิทธิเรียกร้องตามกฎหมาย เมื่อหมดความจำเป็นจะลบ ทำลาย หรือทำให้ข้อมูลไม่สามารถระบุตัวบุคคลได้

PDPA ไม่ได้กำหนดระยะเวลาเดียวที่ใช้กับข้อมูลทุกประเภท การกำหนดอายุข้อมูลจึงต้องพิจารณากฎหมายเฉพาะของกิจกรรมนั้น สัญญา ความจำเป็นทางธุรกิจ ความเสี่ยง และการแจ้งไว้ใน Privacy Policy ห้ามใช้คำว่า “เก็บตลอดไป” โดยไม่มีเหตุผลที่ชัดเจน

หากข้อมูลอยู่ระหว่างข้อพิพาท การตรวจสอบ เหตุข้อมูลรั่วไหล คำขอใช้สิทธิ หรือหน้าที่ตามกฎหมาย อาจระงับการลบเฉพาะข้อมูลที่เกี่ยวข้องไว้ชั่วคราวได้ เรียกว่า **Legal Hold**

## 2. ขอบเขตข้อมูลที่อยู่ภายใต้นโยบาย

นโยบายนี้ใช้กับข้อมูลในเว็บไซต์และระบบ ChauatGo รวมถึงข้อมูลของลูกค้า ร้านค้า ไรเดอร์ ทีมงาน และผู้ติดต่อ ได้แก่

- บัญชีผู้ใช้และข้อมูลติดต่อ
- ข้อมูลร้านค้าและข้อมูลสมัครไรเดอร์
- เอกสารยืนยันตัวตน ใบขับขี่ ทะเบียนรถ และเอกสารประกอบ
- คำสั่งซื้อ รายการสินค้า การจัดส่ง และค่าบริการ
- GPS จุดรับส่ง เส้นทาง และประวัติสถานะงาน
- แชท รีวิว คะแนน ข้อร้องเรียน และการติดต่อฝ่ายบริการ
- รูปพัสดุ รูปสินค้า และไฟล์แนบ
- ข้อมูลการชำระเงิน การจ่ายเงิน บัญชี และภาษี
- Log การใช้งาน Audit Log Security Log และ Incident Record
- Cookie ตัวระบุอุปกรณ์ Analytics และข้อมูลทางเทคนิค
- Backup, Export, Cache, Temporary File และข้อมูลที่อยู่กับผู้ให้บริการภายนอก

## 3. วิธีเริ่มนับระยะเวลาเก็บ

ให้กำหนด “จุดเริ่มนับ” แยกตามข้อมูล ไม่ใช้วันที่สมัครสมาชิกเป็นจุดเริ่มของทุกอย่าง ตัวอย่างจุดเริ่มที่ใช้ได้คือ

- ข้อมูลบัญชี: วันที่ปิดบัญชี หรือวันที่ไม่มีการใช้งานตามเกณฑ์ที่ประกาศ
- คำสั่งซื้อ/งานจัดส่ง: วันที่งานเสร็จ ยกเลิก หรือปิดข้อพิพาท แล้วแต่วันที่หลังสุด
- เอกสารสมัคร: วันที่ไม่ผ่านการสมัคร วันที่ยกเลิกการสมัคร หรือวันที่สิ้นสุดความสัมพันธ์
- GPS: วันที่งานเสร็จหรือยกเลิก
- แชท/ข้อร้องเรียน: วันที่ปิดเรื่อง
- ข้อมูลการเงิน/บัญชี: วันที่ทำรายการหรือวันที่สิ้นสุดรอบบัญชีตามกฎหมายที่เกี่ยวข้อง
- Incident Record: วันที่ปิดเหตุและสิ้นสุดการดำเนินการทางกฎหมาย
- Consent Record: วันที่ถอนความยินยอม หรือวันที่สิ้นสุดวัตถุประสงค์

เมื่อมีหลายวัตถุประสงค์ในข้อมูลชุดเดียว ต้องแยกข้อมูลหรือกำหนดอายุจากวัตถุประสงค์ที่มีระยะเวลายาวที่สุดเท่าที่จำเป็น ห้ามเก็บข้อมูลส่วนเกินเพียงเพราะอยู่ในเอกสารเดียวกัน

## 4. ตารางกำหนดระยะเวลาเก็บรักษา

ตารางนี้เป็น **โครงสร้างสำหรับอนุมัติ** ระยะเวลาจริงที่เป็น `[ต้องกำหนด]` ต้องตรวจสอบกับนักบัญชี ทนายความ สัญญา และผู้ให้บริการก่อนประกาศใช้

| บัญชีไรเดอร์ | สมัคร รับงาน จ่ายเงิน รักษาความปลอดภัย | ระหว่างความสัมพันธ์ + [ระยะเวลา] | สัญญา/กฎหมาย/ข้อพิพาท | ลบหรือปกปิดข้อมูลติดต่อ เอกสาร และข้อมูลที่ไม่จำเป็น |
| ข้อมูลร้านค้า | แสดงข้อมูลและจัดการคำสั่งซื้อ | ระหว่างเป็นร้านในระบบ + [ระยะเวลา] | สัญญา/บริการ/ข้อพิพาท | ซ่อนจากระบบสาธารณะ ลบข้อมูลผู้ติดต่อส่วนบุคคลตามกำหนด |

| GPS ขณะรับงาน | นำทาง คำนวณค่าส่ง ตรวจสอบข้อพิพาท | ค่าเริ่มต้นที่แนะนำ: [30–90 วัน] หลังปิดงาน | บริการ/ความปลอดภัย/ข้อพิพาท | ลบพิกัดละเอียด เก็บเฉพาะสถิติรวมถ้าจำเป็น |
| จุดรับส่งและที่อยู่ | ให้บริการจัดส่งและหลักฐานงาน | [ระยะเวลาตามข้อพิพาท/บัญชี] | สัญญา/กฎหมาย/ข้อพิพาท | ปกปิดที่อยู่หรือทำให้เป็นข้อมูลรวม |
| ประวัติคำสั่งซื้อ | บริการ บัญชี การร้องเรียน | [ระยะเวลาตามกฎหมายบัญชี/ภาษีและข้อพิพาท] | สัญญา/กฎหมาย | แยกข้อมูลที่ต้องเก็บทางบัญชีออกจากข้อมูลติดต่อ |

## 5. กระบวนการทบทวนและอนุมัติ Retention Schedule

1. Data Owner ระบุข้อมูล วัตถุประสงค์ ผู้ใช้ข้อมูล และระบบที่เก็บ
2. Privacy Lead ตรวจฐานการประมวลผลและข้อความที่แจ้งใน Privacy Policy
3. ฝ่ายบัญชี/การเงินตรวจหน้าที่เก็บเอกสารทางบัญชี ภาษี และหลักฐานการจ่ายเงิน
4. ฝ่ายปฏิบัติการตรวจว่าระยะเวลาพอสำหรับข้อร้องเรียน การคืนเงิน และข้อพิพาท
5. Security Lead ตรวจผลกระทบต่อ Backup, Log, Monitoring และผู้ให้บริการภายนอก
6. Legal/ผู้มีอำนาจอนุมัติระยะเวลาและข้อยกเว้น
7. บันทึก Version, วันที่มีผล ผู้อนุมัติ และวันที่ทบทวนครั้งถัดไป
8. ทบทวนอย่างน้อยปีละ 1 ครั้ง หรือเมื่อมีบริการใหม่ กฎหมายใหม่ ผู้ให้บริการใหม่ หรือเหตุละเมิด

## 6. ขั้นตอนการลบหรือทำให้เป็นนิรนาม

### 6.1 ก่อนลบ

- [ ] ตรวจว่าไม่มี Legal Hold, DSAR, ข้อพิพาท, เหตุละเมิด หรือหน้าที่ตามกฎหมายที่ยังค้าง
- [ ] ระบุชุดข้อมูลและตัวระบุที่จะลบให้ชัดเจน
- [ ] ตรวจผลกระทบต่อคำสั่งซื้อ การจ่ายเงิน และความต่อเนื่องทางธุรกิจ
- [ ] ขออนุมัติจาก Data Owner หากเป็นการลบข้อมูลจำนวนมาก
- [ ] สร้าง Delete Job ที่มี Run ID และกำหนดขอบเขต ไม่ใช้คำสั่งลบแบบกว้างโดยไม่มี Preview
- [ ] สำรองเฉพาะหลักฐานที่กฎหมายอนุญาตและจัดเก็บในพื้นที่จำกัดสิทธิ์

### 6.2 ระหว่างลบ

- [ ] ลบจาก Primary Database
- [ ] ลบจาก Firebase Storage และไฟล์ Thumbnail/Preview
- [ ] ลบจาก Search Index, Cache, CDN และ Temporary File
- [ ] ลบจาก Export, Spreadsheet, Local Folder และระบบ Ticket ที่ไม่จำเป็น
- [ ] ส่งคำขอลบให้ผู้ประมวลผลและผู้ให้บริการภายนอกตามสัญญา
- [ ] ป้องกันไม่ให้ระบบสร้างข้อมูลเดิมกลับมาโดยอัตโนมัติ
- [ ] ถ้าลบรายบุคคลไม่ได้ด้วยเหตุทางเทคนิค ให้ทำให้ข้อมูลไม่สามารถระบุตัวบุคคลและบันทึกเหตุผล

### 6.3 หลังลบ

- [ ] ตรวจด้วย Query/Report ว่าข้อมูลไม่เหลือในระบบที่อยู่ในขอบเขต
- [ ] ตรวจสิทธิ์ว่าผู้ใช้ทั่วไปไม่สามารถเข้าถึง URL หรือสำเนาเดิม
- [ ] บันทึกจำนวนรายการ เวลา ผู้ดำเนินการ และผลการตรวจสอบ
- [ ] ลบไฟล์ผลลัพธ์ของ Delete Job ที่มีข้อมูลดิบเมื่อไม่จำเป็น
- [ ] อัปเดต DSAR/Incident/Retention Register
- [ ] แจ้งเจ้าของข้อมูลเมื่อเป็นการตอบคำขอใช้สิทธิ

## 7. การทำลายข้อมูลในระบบหลักของ ChauatGo

### Firestore/Database

ใช้ Batch Delete ที่จำกัด Collection และช่วงข้อมูล มีการ Preview จำนวนรายการก่อนลบ และเก็บเฉพาะ Audit Record ที่ไม่เปิดเผยข้อมูลเกินจำเป็น ห้ามใช้บัญชี Admin ร่วมกันเพื่อทำงานลบ

### Firebase Storage

ลบ Object ต้นฉบับ Thumbnail Metadata และ URL ที่เกี่ยวข้อง ตรวจว่าไฟล์ไม่ได้ถูกทำสำเนาไว้ใน CDN หรือเครื่องของผู้ดูแล และใช้ Storage Rules ป้องกันการเข้าถึงไฟล์หลังหมดอายุ

### Firebase Auth

ลบบัญชีเมื่อผ่านขั้นตอนยืนยันและตรวจ Legal Hold แล้ว แยกการลบบัญชีออกจากการเก็บหลักฐานธุรกรรมที่กฎหมายยังจำเป็นต้องเก็บ และตรวจว่า Token/Session ถูกเพิกถอน

### Logs และ Analytics

กำหนด TTL ตามประเภท Log แยกข้อมูลที่จำเป็นต่อความปลอดภัยออกจากข้อมูลวิเคราะห์ ใช้การ Mask หรือ Hash ที่เหมาะสม และไม่เก็บ URL/Query ที่อาจมีข้อมูลส่วนบุคคลโดยไม่จำเป็น

### Backup

กำหนดรอบหมุนเวียน Backup และตรวจว่าสามารถลบหรือทำให้ข้อมูลใน Backup หมดอายุได้จริง หากการลบรายบุคคลจาก Backup ทำไม่ได้ ให้บันทึกข้อจำกัด ใช้การเข้ารหัส จำกัดการกู้คืน และทำลาย Backup ตามรอบที่กำหนด ห้ามนำ Backup เก่ากลับมาใช้โดยไม่ผ่านขั้นตอนลบข้อมูลที่หมดอายุ

---

## 8. Legal Hold

ให้หยุดการลบข้อมูลที่เกี่ยวข้องทันทีเมื่อเกิดกรณีต่อไปนี้:

- มีคดี ข้อพิพาท หรือคำขอจากหน่วยงานรัฐ
- มีคำขอใช้สิทธิที่ต้องตรวจสอบข้อมูลย้อนหลัง
- มีเหตุ Data Breach ที่อยู่ระหว่างสอบสวน
- มีคำสั่งให้เก็บเอกสารหรือหลักฐาน
- มีการตรวจสอบบัญชี ภาษี หรือธุรกรรมที่เกี่ยวข้อง

Legal Hold ต้องระบุเจ้าของ Hold ขอบเขตข้อมูล เหตุผล วันที่เริ่ม ผู้มีสิทธิ์เข้าถึง และเงื่อนไขยกเลิก เมื่อยกเลิก Hold แล้ว Data Owner ต้องทบทวนข้อมูลอีกครั้งและส่งเข้ากระบวนการลบตามปกติ ห้ามใช้ Legal Hold เป็นเหตุเก็บข้อมูลทั้งหมดแบบไม่มีกำหนด

---

## 9. คำขอลบข้อมูลของเจ้าของข้อมูล

เมื่อได้รับคำขอลบผ่าน DSAR Form ให้ตรวจสอบตัวตน ระบุข้อมูลและวัตถุประสงค์ที่เกี่ยวข้อง ตรวจข้อยกเว้นและ Legal Hold แล้วตอบกลับตามกำหนดที่กฎหมายใช้บังคับ หากลบไม่ได้ทั้งหมด ให้ลบส่วนที่ลบได้ อธิบายเหตุผลของส่วนที่ต้องเก็บต่อ และกำหนดวันทบทวนใหม่

เมื่อมีการลบจากคำขอของไรเดอร์ ให้ตรวจว่าข้อมูลค่าตอบแทน ภาษี ประกันภัย หรือหลักฐานข้อพิพาทมีหน้าที่ต้องเก็บต่อหรือไม่ ก่อนลบข้อมูลติดต่อ GPS ละเอียด และเอกสารที่หมดความจำเป็น

---

## 10. การส่งคำสั่งลบให้ผู้ให้บริการภายนอก

ผู้ให้บริการแต่ละรายต้องมีข้อมูลใน Vendor Register อย่างน้อย ได้แก่ ประเภทข้อมูล ประเทศที่ประมวลผล ระยะเวลาเก็บ วิธีลบ Backup ระยะเวลาตอบสนอง และผู้ติดต่อเหตุฉุกเฉิน

เมื่อครบกำหนดหรือมีคำขอลบ ให้ส่ง Delete Request ที่ระบุระบบ ชุดข้อมูล ช่วงเวลา และกำหนดตอบกลับ ห้ามส่งข้อมูลเกินจำเป็น ใช้การยืนยันตัวตนของผู้ขอ และขอหลักฐานการลบหรือการทำให้ไม่สามารถระบุตัวบุคคลได้

---

## 11. การควบคุมสิทธิ์และหลักฐาน

เฉพาะ Data Owner, Privacy Lead และผู้ดูแลระบบที่ได้รับมอบหมายเท่านั้นที่มีสิทธิ์เริ่ม Delete Job หรือเข้าถึงข้อมูลที่รอทำลาย การลบข้อมูลจำนวนมากควรใช้การอนุมัติสองคน (four-eyes approval)

ต้องเก็บ Delete Audit Record โดยไม่เก็บข้อมูลดิบเกินจำเป็น ได้แก่ Delete Run ID, ผู้ขอ, ผู้อนุมัติ, วันที่เวลา, ระบบ/Collection, จำนวนรายการ, ผลสำเร็จ/ล้มเหลว, รายการข้อผิดพลาด และผลการตรวจสอบหลังลบ

---

## 12. การทำลายเอกสารและอุปกรณ์นอกระบบ

- เอกสารกระดาษ: ใช้เครื่องทำลายเอกสารหรือผู้รับจ้างที่ออกหลักฐานการทำลาย
- อุปกรณ์จัดเก็บ: ลบแบบปลอดภัยหรือทำลายสื่อเมื่อเลิกใช้
- เครื่องพนักงาน: ลบไฟล์ Download, Export, Cache และถังขยะตามรอบ
- USB/External Drive: ห้ามใช้เก็บข้อมูลส่วนบุคคลโดยไม่มีการเข้ารหัสและทะเบียนอุปกรณ์
- Screenshot และไฟล์ทดสอบ: ลบหลังใช้และห้ามใส่ข้อมูลจริงในระบบทดสอบ
- กระดาษที่พิมพ์จาก DSAR หรือเอกสารไรเดอร์: เก็บในตู้ล็อกและทำลายเมื่อพ้นกำหนด

---

## 13. ตัวชี้วัดที่ควรติดตาม

- ร้อยละของ Data Asset ที่มี Owner และ Retention Period
- ร้อยละของข้อมูลที่ลบตามกำหนด
- จำนวนข้อมูลค้างลบและอายุค้างเฉลี่ย
- จำนวน Delete Job ที่ล้มเหลว
- เวลาตั้งแต่ครบกำหนดถึงลบสำเร็จ
- ร้อยละของผู้ให้บริการที่ยืนยันการลบครบถ้วน
- จำนวนข้อมูลที่พบใน Backup หลังพ้นกำหนด
- จำนวนข้อผิดพลาดจากการลบผิดชุดข้อมูล
- จำนวน DSAR ที่ดำเนินการภายในกำหนด
