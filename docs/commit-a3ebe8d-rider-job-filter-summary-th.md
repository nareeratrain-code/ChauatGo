## ปัญหาก่อนแก้

ตัวกรองประเภทงานของไรเดอร์ใช้กับรายการงานทั้งหมด รวมถึงงานที่ไรเดอร์รับไปแล้ว เมื่อไรเดอร์เลือกตัวกรอง เช่น “ส่งอาหาร” ระบบอาจซ่อนงานที่กำลังส่งอยู่ซึ่งเป็นประเภท “ส่งด่วน” ทำให้เกิดความเข้าใจผิดว่าไม่มีงาน Active หรือมีงานหายไปจากหน้าจอ

สาเหตุอยู่ที่ `renderJobs()` ใช้ `matchesJobFilter()` กับทั้ง `newJobs` และ `activeJobs` แม้ว่างานสองกลุ่มนี้จะมีความหมายและแหล่งข้อมูลต่างกัน

## แนวทางที่แก้ไข

กำหนดการทำงานเป็นสองส่วนอย่างชัดเจน:

```text
New Jobs    = งานที่ยังรอให้ไรเดอร์รับ → ใช้ Job Filter
Active Jobs = งานที่ไรเดอร์รับแล้ว     → ไม่ใช้ Job Filter
```

### New Jobs

- อ่านจาก `openJobs`
- ตรวจด้วย `riderMayClaim()`
- ตรวจบัญชีไรเดอร์และสถานะออนไลน์
- ใช้ `matchesJobFilter()` เพื่อกรอง `food`, `express` หรือ `all`
- แสดงเฉพาะงานที่ยังรับได้

### Active Jobs

- อ่านจาก `activeMine`
- ใช้ฟังก์ชันใหม่ `isActiveRiderJob(job, myId)`
- แสดงเฉพาะงานที่เป็นของไรเดอร์คนปัจจุบัน
- รองรับสถานะ:
  - `accepted`
  - `picked_up`
  - `customer_paid`
  - `on_the_way`
  - `ready`
- ไม่ผ่าน Job Filter ดังนั้นงานที่รับแล้วจะแสดงเสมอ

## รายละเอียดการเปลี่ยนแปลงรายไฟล์

### 1. `rider.js`

เพิ่มฟังก์ชัน:

```js
function isActiveRiderJob(job, myId) {
  return !!(job && myId && job.riderId === myId && (
    RIDER_ACTIVE_STATUSES.includes(job.status) || job.status === 'ready'
  ));
}
```

ปรับ `renderJobs()`:

```js
const newJobs = openJobs.filter(j =>
  matchesJobFilter(j) &&
  riderMayClaim(j) &&
  riderProfile?.verified && isOnline
);

const activeJobs = activeMine.filter(j =>
  isActiveRiderJob(j, myId)
);
```

ผลลัพธ์คือ Filter มีผลเฉพาะรายการงานใหม่ และไม่สามารถซ่อนงานที่กำลังดำเนินการได้

นอกจากนี้ยังปรับ QA Hook ให้จำลอง `activeMine` จากงานที่เป็น Active ได้จริง เพื่อให้การทดสอบตรวจพฤติกรรมที่ใกล้เคียง Production มากขึ้น

### 2. `rider.html`

เพิ่มข้อความอธิบายใต้ Job Filter:

> ตัวกรองนี้ใช้กับ “งานใหม่” เท่านั้น งานที่รับแล้วจะแสดงใน “งานที่กำลังทำ” เสมอ

ข้อความนี้ช่วยลดความสับสนของไรเดอร์เมื่อเปลี่ยนตัวกรองแล้วรายการ Active ยังคงแสดงอยู่

## ผลกระทบต่อระบบ

### สิ่งที่ดีขึ้น

- งานที่ไรเดอร์รับแล้วไม่หายเพราะ Filter
- ลดความสับสนระหว่างงานใหม่กับงานที่กำลังดำเนินการ
- โครงสร้างข้อมูลตรงกับหน้าจอที่แยก “งานใหม่” และ “งานที่กำลังทำ” อยู่แล้ว
- ไม่เปลี่ยนกติกาการรับงานฝั่ง Server
- ไม่เปลี่ยน Query หลักของ Firestore
- ไม่กระทบการกรองงานที่เสร็จวันนี้

### สิ่งที่ไม่ได้เปลี่ยนใน Commit นี้

- ไม่ได้เปลี่ยน Firebase Callable หรือ Transaction การรับงาน
- ไม่ได้เปลี่ยน Dispatch Algorithm
- ไม่ได้แก้ Expire/Cancel Flow ของ Order
- ไม่ได้เปลี่ยน Push Notification
- ไม่ได้เปลี่ยนสิทธิ์ Firestore
- ไม่ได้ Deploy Vercel ใน Commit นี้

## ข้อเสนอแนะสำหรับการอธิบายทีม

> Commit นี้แก้ปัญหา Job Filter ซ่อนงานที่ไรเดอร์รับไปแล้ว โดยแยก Data Source และกติกาการแสดงผลของ New Jobs กับ Active Jobs ออกจากกันอย่างชัดเจน ตัวกรองอาหาร/ส่งด่วนจะทำงานเฉพาะกับงานใหม่ ส่วนงานที่รับแล้วจะแสดงเสมอจนกว่าจะเสร็จหรือถูกยกเลิก ทำให้ไรเดอร์ไม่พลาดงานที่กำลังดำเนินการและลดความสับสนในการใช้งาน

1. ไรเดอร์มีงานอาหารกำลังส่งอยู่ แล้วมีงานส่งด่วนใหม่เข้ามา

5. เปิดหน้าไรเดอร์สองแท็บพร้อมกัน แล้วตรวจว่า Active Jobs ไม่หาย
6. ทดสอบบนมือถือจอแคบและเครือข่ายช้า
